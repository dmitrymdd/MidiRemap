## Что это

Десктоп-приложение (Windows, Python) для конвертации **барабанных** MIDI-партий из одной раскладки нот
в другую. Вход — `.mid`, содержащий только барабанную дорожку (экспорт из Guitar Pro 8 или файл из интернета).
Выход — тот же `.mid` с перенумерованными нотами.

Сейчас весь проект — `MidiRemap.py` (Tkinter + mido) со схемой GM → SD3, захардкоженной в `NOTE_MAP`.
Цель — структурированное приложение с картами, профилями ремапа и новым UI.

## Ключевые сущности (не смешивать)

1. **Карта нот (NoteMap)** — номер ноты (0–127) → имя. Описывает раскладку инструмента/программы.
   - Одно имя на нескольких нотах — НОРМА (в GP8: Ride (middle) на 51 и 126; в SD3 одна артикуляция доступна с нескольких нот).
     Ошибка — только дубликат номера.
   - Заложить в модель (не обязательно в MVP): флаг «основная нота артикуляции» — нужен при конвертации В плагин.
2. **Профиль ремапа (RemapProfile)** — исходная карта + целевая карта + явные правила
   `исх. нота → цел. нота | удалить | оставить`. Многие-в-одну — ключевой сценарий (артикуляции VST).
   Карты в профиле — ВСТРОЕННЫЕ КОПИИ (профиль самодостаточен), обе необязательны.
   `NOTE_MAP` первой версии = `legacy_profile()` (map + явный delete остальных нот). Это ручная схема
   пользователя, НЕ встроенный шаблон — только в коде и тестах.
3. **MIDI-файл** — музыкальные данные; конвертируется по профилю.

## Принятые решения

- Сопоставление нот делает пользователь. Программа только подсказывает точные и вероятные совпадения
  (нормализация регистра/пробелов); ложная подсказка хуже пустой. Основная ценность — встроенные шаблоны.
- Встроенные шаблоны карт — только по точным данным из самих программ/плагинов, с указанием источника
  и статуса «проверено». `SD3 WITH EZD soundbanks.txt` (старый кастом пользователя) — НЕ использовать.
- Ноты исходника, которых нет в профиле: спросить пользователя (в редакторе профиля один раз; при конвертации —
  только о нотах, реально встречающихся в файле), по умолчанию оставить на том же номере.
  Если этот номер в целевой карте занят другой артикуляцией или отсутствует — явное предупреждение.
- Ремапим все MIDI-каналы (примеры файлов на канале 1, не 10). Предупреждать, если в файле несколько
  треков/каналов с нотами.
- Многие-в-одну: схлопывать дубликаты note_on одной целевой ноты в ТОЧНО один тик, отдельно по дорожке и каналу
  (оставлять большую velocity); из note_off группы оставлять только САМЫЙ ПОЗДНИЙ. Перекрытия на разных тиках
  не трогаем, только считаем в отчёте. Допуск (`merge_window_ticks`) заложен, но пока > 0 → ValueError.
- Правило ноты при конвертации: overrides (решения пользователя на эту конвертацию) > правила профиля >
  keep по умолчанию. Ядро не записывает overrides в профиль. `note_on` с velocity 0 = note_off.
- `convert_midi(src, dst, note_map)` — тонкая обёртка для Tk-UI (ноты вне карты удаляются), возвращает stats.
- Сохранять все не-нотные события, включая unknown_meta; корректно переносить delta time удалённых событий
  (текущая логика `carry` в `convert_midi` верна — это эталон).
- Исходную раскладку MIDI-файла определить автоматически нельзя — выбор карты/профиля обязателен.
- UI: переход с Tkinter на **PySide6** (редактируемые таблицы, HiDPI, нативный DnD в т.ч. drag-out в DAW,
  темы). Сохранить функции текущего UI: DnD внутрь/наружу, Ctrl+V файла, Ctrl+C результата как файла.
- Стиль: тёмные поверхности, акцент `#E18147`, цвета через токены (светлая тема — позже).
- Язык для пользователя — английский: тексты UI, сообщения ядра (предупреждения, ошибки), README.
  Комментарии и docstring в коде — по-русски, общение с Дмитрием — по-русски.
- Пакет `core/` НЕ импортирует Qt. Ядро должно работать из CLI и тестов.
- Плагин — в будущем; переиспользуются данные (формат профиля JSON) и тестовые примеры, не Python-код.
- Сборка: PyInstaller (папкой, не onefile), `.exe` — только в GitHub Releases.

## Форматы (по реальным файлам в samples/)

**REAPER MIDINoteNames** (`samples/maps/`):
- Первая строка `# MIDI note/CC name map`; строки `<номер> <имя>`; ноты обычно по убыванию.
- Встречаются LF и CRLF — поддерживать оба.
- Строки `NO <номер>` — гипотеза: пользовательский порядок строк piano roll REAPER. Не терять при экспорте.
- Неизвестные строки сохранять как есть (заголовок упоминает CC).

**SD3 MIDI In/E-Drums preset** (`samples/sd3_presets/`): текстовый формат со вложенными `{ }`.
- Хранит только ОТЛИЧИЯ от стандартной раскладки SD3.
- `usermap 55 kickR 36 -1` — гипотеза: входная нота, ID артикуляции SD3, её стандартная нота, (CC-зона?).
- `Trafo`/`StoredTrafo` — кривые и пороги velocity; `HatsSplash`, `HatsPedalMode` — хай-хэт.

**Профиль ремапа** (JSON, UTF-8): `"format": 1`, `name`, `source_map`/`target_map` (null или
`{name, names: {"36": "Kick"}, order, extra_lines}`), `rules` — список по возрастанию src:
`{"src": 36, "action": "map", "dst": 36}` / `{"src": 60, "action": "delete"}` / `"keep"`.
Хранилище: ID = имя файла без расширения (санитизация под Windows), отображаемое имя — внутри данных
(у карт .txt поля имени нет — имя = ID). Без `overwrite=True` не перезаписывает; запись атомарная.
