## Что это

Десктоп-приложение (Windows, Python) для конвертации **барабанных** MIDI-партий из одной раскладки нот
в другую. Вход — `.mid`, содержащий только барабанную дорожку (экспорт из Guitar Pro 8 или файл из интернета).
Выход — тот же `.mid` с перенумерованными нотами.

Первая версия была одним файлом `MidiRemap.py` (Tkinter + mido) со схемой GM → SD3 в `NOTE_MAP`; удалена на этапе 6.
Сейчас: ядро `core/`, хранилище, окно PySide6 (`python -m midiremap`) с вкладками Convert | Profiles | Maps
(редактор профилей — видом «кабелями» с перетаскиванием, правым кликом и панелью подсказок; менеджер/редактор карт).
Профили двунаправленные (8b3a: модель, JSON, конвертация, переключатель «→ / ←» на Convert);
страница Profiles перестроена под обе стороны (8b3b1); редактор правит оба направления (8b3b2, переключатель
«→ N | ← M», зеркальный вид ←, двойной клик — основной кабель). Дальше — этап 9 (полировка, релиз).

## Ключевые сущности (не смешивать)

1. **Карта нот (NoteMap)** — номер ноты (0–127) → имя. Описывает раскладку инструмента/программы.
   - Одно имя на нескольких нотах — НОРМА (в GP8: Ride (middle) на 51 и 126; в SD3 одна артикуляция доступна с нескольких нот).
     Ошибка — только дубликат номера.
   - Флаг «основная нота артикуляции» (`NoteMap.primary`) — нужен при конвертации В плагин.
     В UI он называется **«Write to»** (в коде и JSON — по-прежнему `primary`, не переименовывать).
     Выбирается в профиле (во встроенной копии цели); на вкладке Maps не правится и не показывается (8b2d),
     в JSON карты остаётся (старые файлы читаются).
     Не больше одной основной на артикуляцию (имена сравниваются через `normalize_name`); имени на одной ноте
     флаг не нужен; primary — только на существующих нотах. Проверка — `validate_map()`, выбор — `primary_note()`.
2. **Профиль ремапа (RemapProfile)** — исходная карта + целевая карта + явные правила
   `исх. нота → цел. нота | удалить | оставить`. Многие-в-одну — ключевой сценарий (артикуляции VST).
   Карты в профиле — ВСТРОЕННЫЕ КОПИИ (профиль самодостаточен), обе необязательны.
   `NOTE_MAP` первой версии = `legacy_profile()` (map + явный delete остальных нот). Это ручная схема
   пользователя, НЕ встроенный шаблон. При первом запуске (папки `profiles/` ещё нет) `Storage.seed_profiles()`
   создаёт папку и сохраняет его как обычный профиль (без карт, правится и удаляется); удалённый — не возвращается
   (папка уже есть). Особой записи в комбобоксе Convert больше нет.
   Профиль ДВУНАПРАВЛЕННЫЙ (8b3a): второй набор правил — обратные `reverse_rules`
   `нота цели → нота источника | удалить | оставить` (см. «Принятые решения»).
3. **MIDI-файл** — музыкальные данные; конвертируется по профилю.

## Принятые решения

- Сопоставление нот делает пользователь. Программа только подсказывает точные и вероятные совпадения
  (нормализация регистра/пробелов); ложная подсказка хуже пустой. Основная ценность — встроенные шаблоны.
  `core/suggest.py`: `suggest_rules(src_map, tgt_map)` → по `Suggestion(src, dst, kind, target_name)` на ноту,
  kind = exact | probable | ambiguous (несколько нот без основной — выбирает пользователь) | none; никакого нечёткого
  поиска. `apply_suggestions(profile, suggestions, kinds)` — новый профиль, добавляет map только нотам без правила
  (в ядре осталась, UI её не вызывает).
- Подсказки в редакторе профиля (8b2d, кнопки Accept suggestions больше нет): когда пользователь задал обе карты (новый
  профиль или смена карты), ноты БЕЗ правила, чьё имя совпало с целью (`suggestion_targets()` — exact/probable/
  ambiguous), стоят напротив цели с ПУНКТИРНЫМ кабелем (строка — кольцо вместо точки), над сценой — тонкая панель
  «N matches · Apply · ✕» (пояснение — в подсказке). Никаких диалогов; смена карты только пересчитывает пунктир и
  панель. Куда легла бы подсказка — `plan_suggestions()` (логика назначения 8b2c: совпадение номера → n → n, иначе
  Write to, в т.ч. выбранный молча); None — нужен вопрос о Write to (кабель — на первую строку цели).
  Apply — `apply_suggested()`, один шаг отмены; подсказки, которым нужен выбор Write to, пропускаются и остаются
  пунктиром (их число — в подсказке, Apply выключен, если применить нечего). ✕ — скрыть подсказки для этой пары
  карт до повторного открытия профиля. Открытие существующего профиля панель не показывает. Нота, получившая любое
  правило, из подсказок выбывает (снятие правила её не возвращает). Пунктир на мышь не реагирует; правый клик по
  строке-подсказке — зачеркнуть, перетаскивание — как у любой строки.
- `instrument_group(name)` (`core/notemap.py`) — инструмент из имени («Kick: Hit» → «Kick», «Kick (hit)» → «Kick»,
  у GM — None). ТОЛЬКО для показа строк под заголовками групп (Maps, Profiles);
  никогда для сопоставления и подсказок. Группы сравниваются через `normalize_name`.
- Сохранение профиля (8b2c): если у нот исходной карты нет правила — диалог «N notes have no target and will be
  removed.» Список по номеру: флажок «keep on the same number» (по умолчанию СНЯТ), номер, имя в исходной карте,
  имя на этом номере в цели (подсказка-контекст). Маркеров «!»/«≈» нет. Кнопки: Save / Cancel. Неотмеченные →
  delete, отмеченные → явный keep. Ноты с УЖЕ явным keep (старые профили) в диалог не попадают (решение принято).
  После сохранения у всех нот исходной карты есть правило — конвертация спрашивает только о нотах вне исходной
  карты (там keep по умолчанию не изменился). Без исходной карты диалога нет.
  `unassigned_keep_warnings()` и маркеры удалены; `with_explicit_keeps()` в ядре остался, UI его не вызывает.
- Назначение на артикуляцию цели (8b2c, ядро — `assign_plan()` / `assign_to_articulation()` в `core/profile.py`,
  drop на строку цели вне номера и бейджа — зона 3, и Apply подсказок): исходная нота n, чей номер есть среди нот артикуляции
  (T) → n → n, без вопросов. Остальные → Write to артикуляции. Write to нет: ровно одна нота ЭТОГО ЖЕ назначения
  совпала по номеру — она молча становится Write to; совпало несколько или ни одной — один вопрос на назначение
  (тот же диалог, предвыбор — первая совпавшая). Все совпали — Write to не нужен и не выбирается.
- Write to (выбранный молча или ответом) записывается как `primary` во ВСТРОЕННУЮ копию целевой карты профиля, а не
  в карту пользователя в хранилище. Смена Write to (бейдж «+N» в виде «кабелями») — `with_write_to(profile, note)`:
  primary в копии цели, и на новую ноту переводятся ТОЛЬКО правила, шедшие на прежний Write to и не n → n
  (n → n остаётся; правила на другие ноты артикуляции и при отсутствии прежнего Write to — не трогаются).
- Drop на заголовок группы цели (8b2c, `connect_same_numbers()`): каждой перетащенной ноте, чей номер есть среди нот
  группы (все артикуляции группы, в т.ч. скрытые) — n → n. Ноты без совпадения и ноты с уже существующим map
  не трогаются; диалогов нет; статус — «3 of 7 connected». Группа «Not in the target map» не принимает drop.
- Отмена/повтор (8b2c): Ctrl+Z / Ctrl+Y (и Ctrl+Shift+Z) на странице Profiles — стек снимков рабочей копии
  (`_undoable` в `profiles_page.py`, до 200 шагов; снимок — профиль + подсказки): подключение, снятие кабеля,
  зачёркивание, drop на группу, Write to, смена карты, Apply подсказок, Revert, Save (шаг сохранения тоже
  отменяется); ✕ подсказок — не шаг. Очищается при открытии другого профиля, Save не очищает. Клавиши — в подсказках
  счётчика правил и Revert, видимого текста нет.
- Keep убран из UI (8b2c): в пуле только Unassigned и Delete; явный keep (старые профили) — в Unassigned с маркером
  «=» (подсказка «Kept on the same number»), правый клик зачёркивает его, как любую неназначенную. Keep остаётся
  в модели, JSON и конвертации.
- Таблица правил, переключатель Table | Cables и Assign target… (окно выбора цели) убраны (8b2d): единственный вид —
  «кабелями». Ограничение: без целевой карты новые номера цели задать нельзя (цели — только номера из правил).
- Convert без профилей: пустое состояние «No remap profiles yet — create one in the Profiles tab» + кнопка, Convert
  выключен. Под комбобоксом — «<исх. карта> → <цел. карта> · N rules» (нет карты — «no map», нет обеих — «no maps»)
  и кнопка Edit (переход на Profiles с этим профилем). Список профилей обновляется сигналом `profiles_changed`
  (кнопки Refresh нет).
- Проверка профиля по картам — `validate_profile(p, direction=FORWARD)` в `core/profile.py` →
  `ProfileIssue(code, note, message)` (в REVERSE — обратные правила по нотам цели; тексты называют карты профиля:
  «…which is not in the source map», — `direction` передаётся и в `keep_issue()`; строки ядра в UI не правятся):
  map/keep для ноты вне исходной карты (delete для неё — НЕ замечание, 8b2d), map на ноту вне целевой, keep на отсутствующий номер или другую артикуляцию
  (`keep_issue()` — то же для keep по умолчанию), `NO_RULE` — нота без правила: вопрос пользователю, не ошибка.
  map на неосновную ноту артикуляции — норма. `RemapProfile.validate()` и формат JSON не меняются.
  В редакторе (8b2d) панели замечаний нет: строка с замечанием подсвечена (warning_bg), текст — в её подсказке.
- Встроенные шаблоны карт — только по точным данным из самих программ/плагинов, с указанием источника
  и статуса «проверено». `SD3 WITH EZD soundbanks.txt` (старый кастом пользователя) — НЕ использовать.
- Ноты исходника, которых нет в профиле: спросить пользователя (в редакторе профиля один раз при сохранении —
  по умолчанию удалить, см. диалог сохранения; при конвертации — только о нотах, реально встречающихся в файле,
  по умолчанию оставить на том же номере).
  Если этот номер в целевой карте занят другой артикуляцией или отсутствует — явное предупреждение.
- Ремапим все MIDI-каналы (примеры файлов на канале 1, не 10). Предупреждать, если в файле несколько
  треков/каналов с нотами.
- Многие-в-одну: схлопывать дубликаты note_on одной целевой ноты в ТОЧНО один тик, отдельно по дорожке и каналу
  (оставлять большую velocity); из note_off группы оставлять только САМЫЙ ПОЗДНИЙ. Перекрытия на разных тиках
  не трогаем, только считаем в отчёте. Допуск (`merge_window_ticks`) заложен, но пока > 0 → ValueError.
- Правило ноты при конвертации: overrides (решения пользователя на эту конвертацию) > правила профиля >
  keep по умолчанию. Ядро не записывает overrides в профиль. `note_on` с velocity 0 = note_off.
- `convert_midi(src, dst, note_map)` — обёртка поведения первой версии (ноты вне карты удаляются), возвращает stats; нужна характеризационным тестам.
- Сохранять все не-нотные события, включая unknown_meta; корректно переносить delta time удалённых событий
  (текущая логика `carry` в `convert_midi` верна — это эталон).
- Исходную раскладку MIDI-файла определить автоматически нельзя — выбор карты/профиля обязателен.
- UI: переход с Tkinter на **PySide6** (редактируемые таблицы, HiDPI, нативный DnD в т.ч. drag-out в DAW,
  темы). Сохранить функции текущего UI: DnD внутрь/наружу, Ctrl+V файла, Ctrl+C результата как файла.
- Стиль: тёмные поверхности, акцент `#E18147`, цвета через токены (светлая тема — позже).
- Раскладка страницы Profiles (8b3b1; поведение правки не менялось):
  - Заголовок — ОДНА строка: `[профиль ▾] [⋯] статус … [→ N | ← M] … [↻] [Revert] [Save]` (переключатель — по центру
    строки: `QGridLayout`, левая и правая колонки поровну; доработки 8b3b2). Комбобокс профилей
    заменил список слева (боковой панели и кнопки «« / »» больше нет, старый ключ `profiles/sidebar_collapsed` в
    `ui.ini` игнорируется): имя, «•» перед именем при несохранённых правках, подсказка пункта — сохранённое
    состояние («карты · N rules»); нечитаемый профиль — неактивный пункт; без профилей — «No profiles yet».
    Смена профиля с правками спрашивает, как раньше (Cancel возвращает выбор). Меню «⋯»: New, Rename, Duplicate,
    Delete — те же действия и подтверждения; три точки «⋯» рисуются сами (`DotsButton`, глиф шрифта на 100 % мелкий),
    кнопка размером с ↻; все контролы строки — одной высоты (`_fit_header()` при показе, когда стиль окна уже
    применён). `direction_slot` справа от «⋯» — переключатель направления (8b3b2, см. «Редактор обратной
    стороны»). Статус (последнее действие) — в той же строке, длинный обрезается.
  - Колонки — симметрично, `QSplitter` из трёх: левый пул | сцена (колонки 2–3) | правый пул. Над каждой — строка
    высотой `HEAD_H` (`left_head` / `mid_head` / `right_head` в `CableEditor`): карта источника над левым пулом,
    счётчик «N rules · M unassigned» и панель подсказок над сценой, карта цели над правым пулом (подписей
    SOURCE/TARGET MAP и стрелки нет — смысл в подсказках кнопок). Всё остальное по высоте — сцене.
  - Правый пул (`CableEditor.pool_right`) — зеркало левого: своя прокрутка, та же минимальная ширина, граница тянется,
    ширина — в `ui.ini` (`cables/pool_right_width`). С 8b3b2 — пул нот цели (активен в ←); drop не принимает ни
    один пул (цель drop — только сцена).
  - Ширины пулов применяются точно при первом показе вида (`_apply_pool_widths`: до показа QSplitter масштабирует
    их пропорционально). Ширины колонок сцены — доли ширины (`cables/columns`); все границы колонок сцены тянутся
    (зоны захвата со стороны промежутка, курсор ↔, тонкая линия-направляющая; справа может остаться свободное место).
  - Настройки — `ui.ini` в папке хранилища (`ui/settings.py`, QSettings INI — тесты с временным хранилищем настройки
    пользователя не трогают). Имя или подпись группы обрезаны — полный текст первой строкой подсказки.
- Текстовая диета UI: интерфейс лаконичный, пояснения — в подсказках (tooltip), а не видимым текстом. Кликабельные
  карточки — курсор-рука, подсветка при наведении и подсказка («Click or drop to replace», «Click to show in folder»).
  Видимыми остаются содержимое, статус и то, что требует действия (панель замечаний, список в диалоге сохранения,
  ошибки). Профиль с несохранёнными правками в комбобоксе — «•» перед именем (подсказка — сохранённое состояние).
  Горячие клавиши — в подсказках кнопок/зон («Convert (Enter)», «Copy file (Ctrl+C)», Esc — в подсказке зоны файла),
  отдельной строки клавиш нет. Статус после конвертации — «Converted: <имя файла>».
- Язык для пользователя — английский: тексты UI, сообщения ядра (предупреждения, ошибки), README.
  Комментарии и docstring в коде — по-русски, общение с Дмитрием — по-русски.
- Пакет `core/` НЕ импортирует Qt. Ядро должно работать из CLI и тестов.
- Карты хранятся в JSON; REAPER MIDINoteNames `.txt` — только импорт/экспорт (Export .txt — вся карта; экспорт
  «Write to notes only» из UI убран в 8b2d, в ядре `primary_only` остался).
- Вкладка Maps (8b2d): столбцы NOTE | PITCH | NAME (WRITE TO и SAME NAME убраны); имя на нескольких нотах — бейдж
  «+N» рядом с именем (как в виде «кабелями», `NameDelegate`), номера — в подсказке; дубли без Write to не
  подсвечиваются и не попадают в замечания.
- Редакторы карт и профилей: правка — в рабочей копии; карта сохраняется через `finalize_edit(base, edited)` (статус, `order`, чистка primary);
  копия шаблона — `duplicate_map(..., from_template=True)`. Экспорт берёт карту как в редакторе (с несохранёнными
  правками). Переключение вкладок правки не теряет и не спрашивает; спрашивает смена карты/профиля,
  New/Import/Duplicate/Rename и закрытие окна.
- `meta` при копировании карты (в т.ч. из шаблона и в профиль): `source` сохраняется; правка имён, добавление или
  удаление нот → `status` = "unverified"; изменение только флагов primary статус не меняет.
- Названия нот по высоте: 60 = C3 (соглашение Toontrack, SD3 показывает 36 как C1) — `core/pitch.py`, `OCTAVE_OFFSET`.
- Плагин — в будущем; переиспользуются данные (формат профиля JSON) и тестовые примеры, не Python-код.
- Двунаправленные профили (8b3a, ядро — `core/profile.py`):
  - `RemapProfile.reverse_rules` — обратные правила (ключ — нота ЦЕЛЕВОЙ карты, `dst` — нота исходной), та же форма
    `Rule`. `None` — не заданы, действуют выведенные из прямых (`derive_reverse()`); рабочий набор —
    `effective_reverse()`. Все старые профили (формат 1) — `None`.
  - Выведение (`derive_reverse()`): нота цели b, на которую идут прямые map, — b → b, если среди них есть сама b,
    иначе b → наименьшая из них; прочие ноты той же артикуляции цели (алиасы) без входящих кабелей — то же, что
    у Write to артикуляции, если у него есть правило, иначе — что у наименьшей её ноты с правилом; остальные ноты
    цели правила не получают (в 8b3b2 — правый пул Unassigned). keep — не кабель, обратного правила не порождает.
  - Основной кабель НЕ хранится отдельно: прямой a → b основной ⇔ обратное правило b — b → a (`primary_pairs()`).
    Пока обратные правила выводятся, это ровно прежнее правило показа 8b2d (тест совпадения — `test_reverse.py`).
  - `reversed()` — профиль обратного направления (карты поменяны, `rules` = `effective_reverse()`,
    `reverse_rules` = прямые). Обратная сторона переиспользует convert/validate/suggest/assign через него, без
    дублирования; Write to на артикуляцию ИСХОДНОЙ карты ляжет в `primary` её встроенной копии (8b3b2).
    Инволюция по содержанию: при `reverse_rules = None` `reversed().reversed()` делает выведенные заданными явно —
    сравнивать через `to_dict()`, не `==`. `oriented(FORWARD | REVERSE)` — сам профиль или `reversed()`.
  - `sync_reverse(before, after)`: заданное обратное правило, равное выведенному из `before`, следует за правкой
    прямых (заменяется выведенным из `after` или убирается); отличающееся (ручное, 8b3b2) не трогается; `None`
    остаётся `None`. В редакторе — в обёртке `_undoable` (тот же шаг отмены, снимок отмены хранит и обратные).
  - Смена исходной или целевой карты в редакторе сбрасывает `reverse_rules` в `None` (тем же шагом отмены):
    обратные правила по нотам прежней карты не переживают смену.
  - Полнота — статус, а не требование: `missing_rules(p, direction)` — ноты карты исходной стороны направления без
    правила. Конвертация без правил — как раньше (спрашивает только о нотах из файла, по умолчанию keep).
  - Конвертация: `convert(..., direction=FORWARD | REVERSE)` и `analyze(..., direction)` — через `oriented()`.
  - `normalized_reverse(p)`: обратные правила, равные выведенным, хранятся как `None` — при чтении JSON и после
    каждой правки в редакторе (`_undoable`). Поведение то же (`sync_reverse` ведёт их одинаково).
  - Основной кабель двойным кликом (8b3b2, ядро): `with_primary_cable(p, a, b)` (→, кабель a → b) — обратное
    правило b → a; алиасы той же артикуляции цели без своих кабелей, чьё правило скопировано с b (b — их донор по
    `derive_reverse`: Write to с кабелями, иначе наименьшая нота с кабелями), переходят на a вместе с b; ручные
    правила алиасов не трогаются. `with_forward_primary(p, a, b)` (←, кабель b → a) — прямое правило a → b вместо
    прежнего a → b'; выведенные для b' обратные следуют (`sync_reverse`). Постусловие обоих — (a, b) в
    `primary_pairs()`; если синхронизация сдвинула правило b — `pin_primary()` ставит b → a явно (по разбору
    `sync_reverse` этого не бывает: у b в этом случае ровно один входящий кабель — от a; ветка защитная, тест —
    через подмену). Уже основной — ничего.
  - Convert: кнопка «→ / ←» справа от комбобокса (направление общее для всех профилей, запоминается в `ui.ini`,
    ключ `convert/direction`); строка под комбобоксом — карты и число правил в выбранном направлении
    (`profile_summary(p, direction)`); в отчёте — «Profile: <имя> (reverse)».
- Редактор обратной стороны (8b3b2):
  - Переключатель «→ N | ← M» — ОДИН сегментированный контрол по центру строки заголовка (`direction_toggle`,
    `QFrame#segmented` с общей рамкой, внутри `direction_slot` с двумя кнопками `segment` без своих рамок, между ними —
    разделитель; выбранный → — фон `selection` и цвет `accent`, выбранный ← — `reverse_selection` и `reverse`; высота —
    как у остальных контролов, рамка строку не раздувает); N, M — `missing_rules()` по направлениям, обновляются при каждой правке; подсказка «N source/target
    notes have no rule in this direction» (нет карты — только стрелка). Профиль открывается в →. Переключение — НЕ шаг
    отмены. Счётчик над сценой и панель подсказок — по направлению вида.
  - ← — работа над `work.reversed()`, картинка ЗЕРКАЛЬНАЯ (не переставленные колонки): исходная карта слева,
    целевая справа. `[левый пул — неактивен] [артикуляции исходной карты] кабели [подключённые ноты цели] [правый пул]`.
    `cable_layout.py` не менялся (без Qt): в ← `build_layout(work.reversed(), …)`; зеркалит только `cable_view.py`
    (`CableEditor.direction`, `.shown` = `oriented(direction)`, `.mirrored`): те же доли ширины колонок и тянущиеся
    границы, в левой колонке сцены — строки цели вида (точка справа), в правой — подключённые строки (точка слева),
    рамка связки — справа; кабель рисуется от точки артикуляции к точке ноты (всегда слева направо), касательные
    превью развёрнуты (тянут справа налево). Активный пул в ← — правый (ноты цели без обратного правила,
    Unassigned / Delete по группам целевой карты); выделение, Shift-диапазон, автопрокрутка, якоря превью — у
    активного пула.
  - Неактивный пул — `build_layout(другое направление, collapsed=BLOCKS)`: только заголовки блоков с числами,
    приглушены (`INACTIVE`), на мышь не реагируют (`view_press` поглощает), пояснение — в подсказке.
  - Сигналы вида несут ноты и slot ОРИЕНТИРОВАННОГО профиля; страница вызывает ядро на `_oriented()` и пишет назад
    `_put()`: в → — карта цели и прямые правила; в ← — `work.source_map = new.target_map` (Write to — в копию ИСХОДНОЙ
    карты) и `work.reverse_rules = new.rules`. Так работают drop на артикуляцию (assign_plan / assign_to_articulation,
    вопрос Write to), «+N» (with_write_to), правый клик, зачёркивание, drop на группу, Apply подсказок.
  - Цвет: кабели, точки, обводка цели при drop, превью — токен направления (`TONES`): → `accent`, ← `reverse`
    (#4FB0C6, наведение `reverse_hover` #74C4D6). Рисуются кабели только активного направления.
  - Подсказки — свои у направления (`_suggest[direction]`): для ← `suggestion_targets(target_map, source_map)` по
    нотам цели без обратного правила; ✕ скрывает для пары карт в текущем направлении. Свёрнутость (collapsed /
    show_all / expanded) — своя у направления (`_ViewState`), по умолчанию при открытии профиля.
  - Переключение направления пересортировывает; группа вверху видимой части сцены (ключ — `normalize_name` подписи)
    после перестройки снова вверху, нет такой — к началу (только показ, не сопоставление).
  - Двойной клик по кабелю — сделать основным (`primary_requested` → `make_primary`, один шаг отмены; ядро — см.
    8b3a выше). Статус: «Reverse: b → a (was b → x)» в →, «Forward: a → b (was a → b')» / «(was unassigned)» в ←.
    Подсказка «Double-click to make primary» — только у неосновных кабелей. Первое нажатие двойного клика по кабелю
    ничего не делает (не перетаскивание, не выделение). После двойного клика связка этой цели сразу
    пересортировывается — основной кабель первым (`CableEditor.bring_primary_first` → `primary_first()`).
  - Связка напротив одной цели: строки с основным кабелем — первыми, остальные — по номеру (`_bundle_order` в
    `fresh_order`, т.е. при пересортировке; при замороженном порядке новые строки по-прежнему встают в конец). Номер
    основного кабеля на строке цели (`TargetRow.lines`) — верхний; у раскрытых алиасов первая строка — их заголовок
    без кабеля, номера — под ним. Строка алиасов «+N» и заголовок раскрытых — на месте первой ноты места, их ноты —
    по возрастанию; строки нот под заголовком — в порядке связки. Пример ←: SD3 35 «Kick: Hit» (основной) над
    34 / 36 «Kick: Open». Параллельные кабели между совпадающими номерами-дублями (11 → 11 и 119 → 119 внутри
    «Hi-Hat: Closed Tip») — так и задумано: каждый номер цели — на своей строке, со своим основным кабелем.
  - Двойной клик по строке Unassigned (только этот блок, не Delete) — подключить на тот же номер
    (`same_number_requested` → `ProfilesPage.connect_same_number`, один шаг отмены): каждая нота строки (у «+N» —
    все) — n → n, если номер есть в карте другой стороны (`connect_same_numbers`); остальные остаются в пуле, статус
    «… · not in the target map: …»; не совпала ни одна — «No note <n> in the target map» (в ← — «source map»).
    Номер свободен (кабелей на него нет) — кабель основной, как обычно. Номер занят — новый кабель НЕОСНОВНОЙ: в →
    выведение предпочло бы n → n, поэтому `keep_existing_primary(before, after, numbers)` (ядро) возвращает обратные
    правила номера и его алиасов без своих кабелей к прежним (явно); в ← прямое правило исходной ноты не трогается —
    неосновной сам собой (основной в ← задаёт прямое правило: если оно уже n → n, новый кабель и станет основным).
    Строка уходит из пула напротив цели, сцена прокручивается к ней минимально (`CableEditor.reveal`, `ensureVisible`;
    уже видна — без движения). Первое нажатие двойного клика лишь выделяет строку; подсказка строк Unassigned —
    строка «Double-click to connect to the same number».
  - Drop на строку артикуляции цели — три зоны (в обоих направлениях; решает точка отпускания,
    `_Row.zone_at` → `_Drag.zone`): (1) ЛЮБОЙ видимый номер на строке (`TargetRow.numbers`: использованные номера, без
    кабелей — Write to или первая нота; в т.ч. Write to и номер первой строки рядом с именем; зона — номер и высота
    ноты, `number_rect`; Write to без кабеля при кабелях на другие ноты не показан — он за бейджем, см. (2))
    — map РОВНО на эту ноту
    (`note_drop_requested` → `assign_note`; логики Write to и вопросов нет; строка «+N» — все её ноты туда же);
    (2) бейдж «+N» / «…» — при отпускании меню ВСЕХ нот артикуляции «Connect to» (`pick_destination`, то же
    оформление, что меню Write to — `notes_menu`, текущий Write to отмечен), выбор — куда пойдёт кабель, Write to не
    меняется; Esc / мимо — ничего; (3) остальное (имя, пустое место) — логика 8b2c, как раньше. Drop на заголовок
    группы — без изменений. При перетаскивании: над номером обведён только он (уже обводки строки), над бейджем —
    бейдж подсвечен, иначе — строка. Подсказка строки цели — «Drop on a number to connect to that note». Каждый drop —
    шаг отмены; основной кабель и порядок связки — по общим правилам (перенос неосновного кабеля основной не
    трогает); повторный drop подключённой строки на другой номер той же артикуляции — перенацеливает. Пример ←:
    EZD3 «Crash 1: Bow» (84, 87), SD3 88 и 85 — 88 → 84, 85 → 87 (через зону 3 оба легли бы на Write to 87).
  - Комбобоксы (профиль на Profiles и на Convert) — `ui/combo.py` `ComboBox`: у `::drop-down` нет своей рамки
    (была двойная граница справа), `::down-arrow` скрыт, стрелку-треугольник рисует `paintEvent` (как точки
    `DotsButton`; треугольник рамками в стиле Qt рисует прямоугольником). Контейнер списка — отдельное окно, стиль
    главного окна до его полей не доходит (белые полосы) — `showPopup` задаёт ему цвета явно. Кнопки выбора карты —
    `QPushButton` с меню (штатный индикатор), их это не касалось.
  - Отмена/повтор — один стек на оба направления; снимок = профиль (с обратными правилами), подсказки обоих
    направлений и направление шага. Ctrl+Z / Ctrl+Y сначала переключают вид на направление шага (не шаг), затем
    восстанавливают. `_undoable`: `sync_reverse` после правки (кроме действий, сами согласовавших обратные —
    `_reverse_done`), затем `normalized_reverse`. Правки в ← прямых не меняют; отличающиеся от выведенных обратные
    правила — ручные (sync их не трогает).
  - Сохранение: диалог — только прямое направление (ноты исходной карты без прямого правила); ноты цели без
    обратного правила не спрашиваются и остаются без правила (полнота — статус; конвертация спрашивает, как раньше).
    Подсказка Unassigned в ←: «No rule in this direction: kept on the same number when converting».
- Сборка: PyInstaller (папкой, не onefile), `.exe` — только в GitHub Releases.

## Форматы (по реальным файлам в samples/)

**REAPER MIDINoteNames** (`samples/maps/`):
- Первая строка `# MIDI note/CC name map`; строки `<номер> <имя>`; ноты обычно по убыванию.
- Встречаются LF и CRLF — поддерживать оба.
- Строки `NO <номер>` — гипотеза: пользовательский порядок строк piano roll REAPER. Не терять при экспорте.
- Неизвестные строки сохранять как есть (заголовок упоминает CC).

**SD3 MIDI In/E-Drums preset** (`samples/sd3_presets/`): текстовый формат со вложенными `{ }`.
- Хранит только ОТЛИЧИЯ от стандартной раскладки SD3.
- `usermap 55 kickR 36 -1` — гипотеза: входная нота, ID артикуляции SD3, её стандартная нота, (CC-зона?).
- `Trafo`/`StoredTrafo` — кривые и пороги velocity; `HatsSplash`, `HatsPedalMode` — хай-хэт.

**Карта нот** (JSON, UTF-8): `{"format": 1, "kind": "notemap", "name", "names": {"36": "..."}, "primary": [..],
"order": null | [..], "extra_lines": [..], "meta": {"source": str|null, "status": "verified"|"unverified",
"notes": str|null}}`. Экспорт в REAPER: `export_notenames(map, primary_only=False)` (UI — только полная карта); при `primary_only=True` —
одна нота на артикуляцию (основная или единственная), артикуляции с дублями без основной пропускаются
(список — `primary_only_notes()`), строки `NO` — только для экспортированных нот.

**Профиль ремапа** (JSON, UTF-8): `"format": 2` (пишется всегда; читаются 1 и 2), `name`, `source_map`/`target_map`
(null или `{name, names: {"36": "Kick"}, primary, order, extra_lines, meta}`; `primary` и `meta` (как в JSON карты)
необязательны — старые профили читаются; `primary` есть у ОБЕИХ карт — Write to цели и, с 8b3b2, источника),
`rules` — список по возрастанию src: `{"src": 36, "action": "map", "dst": 36}` / `{"src": 60, "action": "delete"}` /
`"keep"`; `reverse_rules` — та же форма (src — нота цели, dst — нота источника). `reverse_rules` пишутся всегда
(действующие: заданные или выведенные), поэтому первое сохранение из редактора их фиксирует. Формат 1 и формат 2
без поля → `reverse_rules = None`; при чтении набор, равный выведенному, тоже становится `None` (поведение то же —
`sync_reverse` ведёт их одинаково; прочитанный и созданный профиль равны через `==`). Старые версии программы
формат 2 не читают (релизов ещё не было).

**Хранилище**: ID = имя файла без расширения (санитизация под Windows), отображаемое имя — внутри данных.
Без `overwrite=True` не перезаписывает; запись атомарная. Карты — `maps/*.json`; старые `maps/*.txt` читаются
как legacy (`Entry.legacy`, имя = ID), `.json` с тем же ID скрывает `.txt`. Запись карты — всегда `.json`;
legacy `.txt` с тем же ID занимает ID (нужен `overwrite=True`) и после записи удаляется; `delete_map` удаляет оба.

**Встроенные шаблоны карт**: `src/midiremap/templates/maps/*.json`, генерируются `tools/build_map_templates.py`
из `samples/maps/*.txt` (метаданные — в скрипте, только по фактам ниже; флагов primary нет — нет данных).
`tests/test_templates.py` проверяет совпадение. Загрузка — `midiremap.templates.list_map_templates()` /
`load_map_template(id)`. Все четыре — verified (General MIDI и Guitar Pro 8 — по ручной проверке Дмитрия,
источник в метаданных не указан). Для сборки нужен `collect_data_files("midiremap.templates")` — пометка в spec.

## Этап 8b2 — визуальный редактор профиля (план)

- Три колонки слева направо: (1) ПУЛ — блоки Unassigned / Delete (Keep убран в 8b2c), внутри группы исходного инструмента,

  и начинаются сверху (над целями пусто не бывает).

- Подключённые исходные строки встают напротив своей цели: связка 10-в-1 = высокая строка цели и десять строк

Сделано в 8b2a (решения):
- Вид — `CableEditor` (`ui/cable_view.py`): QSplitter из двух QGraphicsView — пул (`.pool`) и сцена колонок 2–3
  с кабелями (`.view`) — плюс прозрачный для мыши слой `CableOverlay` поверх обоих (кабель-превью рисуется

- Раскладку считает `ui/cable_layout.py` без Qt: `build_layout(profile, collapsed, snapshot, show_all, expanded)`
  → `CableLayout` с отдельными `.pool` (PoolLayout) и `.scene` (SceneLayout), координаты в строках каждой раскладки;
  `fresh_order()` / `update_order()` → `OrderSnapshot` (порядок — по нотам, не по строкам). Кнопка «↻»
  (Refresh layout) — над сценой (переключатель Table | Cables убран в 8b2d).
- Цель — строка на артикуляцию (normalize_name), показывает Write to (или первую ноту) и «+N» при нескольких нотах;
  map на неосновную ноту — кабель к той же строке. map на номер вне целевой карты — строка в группе
  «Not in the target map» (без целевой карты — строки по номерам, без групп).
- Порядок ЗАМОРОЖЕН между пересортировками: подключили (или переподключили) — строка сразу уходит из пула и встаёт
  в колонке 2 напротив цели (в конец её строк); сняли кабель — строка остаётся в колонке 2 на своём месте, без кабеля,
  приглушённая (`SourceRow.stale`), после пересортировки возвращается в пул; смена состояния без подключения
  (напр. зачеркнули) — строка остаётся в своём блоке пула, зачёркнутая.
- Пересортировка: кнопка «↻», смена режима группы цели, ✕ подсказок, а также открытие профиля, Revert,
  Save и смена карты (это не правки правил, а смена всего содержимого). Сворачивание в ПУЛЕ и раскрытие алиасов
  перестраивают только свою колонку при том же порядке (колонки 2–3 не двигаются).
- Сворачивается каждый блок и группа пула (клик по заголовку); заголовок показывает число нот. По умолчанию свёрнут
  Delete (до 8b2c — Keep и Delete); при открытии другого профиля — снова по умолчанию (как и режимы групп цели и раскрытые алиасы),
  после Save/Revert состояние сохраняется.
- Строки: номер, высота ноты, имя (выровненные столбцы), скругление, лёгкий фон при наведении; Delete — зачёркнуто

  Заголовки — приглушённые, шеврон сворачивания, уровень блока — мелкими капителями.

Сделано в 8b2b (решения):
- Алиасы источника свёрнуты ТОЛЬКО В ПОКАЗЕ: ноты одного места (блок пула или строка цели) с одним именем
  (normalize_name) — одна строка «Snare: Center ×7» (`SourceRow.notes`; номера — в подсказке), один кабель
  (`Cable.notes`). Правила в модели и JSON — по-прежнему по нотам; любое действие со строкой — со всеми её нотами.
  Шеврон справа раскрывает строку: заголовок алиасов + строка на ноту (с отступом), чтобы развести алиасы по разным
  целям. Ключ раскрытия — «<место>|<имя>» (место — блок или slot), т.е. раскрытие действует только в своём месте.

  Заголовки групп пула считают НОТЫ, не строки.
- Группы цели — два режима: «только подключённые» (по умолчанию: видны артикуляции, напротив которых есть строки,
  в т.ч. без кабеля до пересортировки; группа без них — один заголовок) и «все» (`CableEditor.show_all`). Заголовок —
  «подключено / всего» артикуляций (или просто «всего», если подключённых нет). Клик — смена режима с пересортировкой.
  Плоская цель без групп (GM) — всегда все строки. Заменяет «свёрнутую группу с кабелями на заголовке» из 8b2a.
- Перетаскивание — своя обработка мыши во view (не QDrag): нажатие на строку пула или колонки 2 → после

  таймер 16 мс; с нескольких выделенных строк — по кабелю от каждой). Выделение: клик, Ctrl — добавить/убрать,
  Shift — диапазон в той же колонке. Отпустили на строке цели → сигнал `connect_requested(notes, slot)` → страница:
  `assign_articulation` (правило совпадения номеров — см. «Принятые решения», 8b2c; Cancel в вопросе Write to —
  без изменений) или `assign_note` для номера вне целевой карты; прежние правила этих нот (delete/keep/map)
  заменяются. Мимо цели или Esc — ничего.
  Автопрокрутка — у той колонки, над которой курсор (зона 32 px у края и за ним). Цель под курсором обведена.
  Наведение на заголовок группы со скрытыми артикуляциями ~500 мс во время перетаскивания включает «все»
  (перестраивается только сцена, порядок тот же) и группа так и остаётся открытой.
- Правый клик действует сразу, без меню (страница: `clear_rules` / `toggle_strike`): кабель (зона попадания 16 px)
  или подключённая строка колонки 2 — снять кабель (правило убрать), строка остаётся приглушённой до пересортировки;
  строка пула в любом блоке или строка колонки 2 без кабеля — зачеркнуть (delete) / вернуть (без правила);
  заголовок группы пула (уровень 1, в любом блоке) — зачеркнуть всю группу, а если уже вся зачёркнута — вернуть всю.

  Правый клик действует на одну строку, даже если выделено несколько.
- Бейдж «+N» строки цели кликабелен: меню нот артикуляции (номер, высота), текущий Write to отмечен; выбор →

Сделано в 8b2c (решения; логика назначения, Write to, группа, отмена, Keep — в «Принятых решениях»):
- Номера на стороне цели: строка артикуляции показывает номера, на которые реально идут правила

## Правила работы

- Маленькие проверяемые шаги; после каждого приложение рабочее. Не переписывать всё сразу.
- Тесты (pytest) — вместе с каждым этапом ядра.
- Архитектурные изменения — сначала объяснить последствия и альтернативы.
- Не выдумывать форматы и раскладки плагинов — только по реальным файлам/данным.
- В сообщения коммитов НЕ добавлять строки Co-Authored-By и прочую атрибуцию.
- Скриншоты — ТОЛЬКО отрисовкой собственных виджетов приложения (`QWidget.grab()` / offscreen-рендер; всплывающее
  меню — своим `grab()`, наложенным на снимок окна), НИКОГДА не захватом экрана (`QScreen.grabWindow` и т.п.):
  окно может оказаться не на переднем плане, и в снимок попадёт чужое содержимое экрана. В offscreen без шрифтов
  текст — квадратики: `QT_QPA_FONTDIR=C:\Windows\Fonts`. Диалог (в т.ч. вопрос Write to — `write_to_dialog()`)
  снимается своим `grab()` и накладывается на снимок окна.
